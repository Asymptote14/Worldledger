# WorldLedger 对照实验协议

目的不是证明“故事更好看”，而是检验一个可证伪命题：

> 在相同模型和可比推理预算下，把 LLM 作为受约束的状态转移提案者，是否比
> 纯提示词或检索记忆方案更稳定地维护长期事实、知识边界、动作承诺和因果链。

## 共同纪律

1. 三组使用同一模型、温度、世界描述、玩家输入和时间跨度。
2. 保存每次请求、响应、输入/输出 token、错误重试和最终状态；失败调用也计费。
3. 测试开始后不得修改引擎、提示词、检索参数、评分脚本或预期答案。
4. 系统名称在人工盲评中改成 A/B/C；评审不得知道哪组是 WorldLedger。
5. 模型不得给自己的输出打分。能机械判断的项目必须由脚本判断。
6. 同时报告两种口径：同一玩家脚本下的质量与实际成本，以及每 10k token 的
   有效状态转移数。不要只报告“同调用数”。
7. 第一轮是 pilot，只用于发现协议 bug。修正协议后必须整轮重跑，不能只补跑
   输掉的组。

## 方案一：低成本同世界盲测（WorldLedger vs 纯提示词）

### 要回答的问题

在一个 12 步、跨 5 天的相同世界里，纯提示词是否会比 WorldLedger 更容易：

- 算错时间或提前触发事件；
- 让不在场的人出现、对话或接受物品；
- 忘记进行中的行动，或让行动无故完成；
- 让不知道秘密的人使用秘密；
- 让物品无因出现、消失或改变持有者。

### 两组定义

**A. WorldLedger**

- 使用当前引擎，不改代码。
- 输出玩家可见切片，同时保存完整 JSON 账本。
- 不把内部账本直接展示给玩家。

**B. 纯提示词**

- 无数据库、无结构化状态、无校验器、无外部记忆。
- 每轮只重发世界描述与此前累积文本。
- 可以分“玩家所见 / 世界内部”，但两部分都会进入下一轮上下文。
- 提示词应明确要求维持时间、位置、记忆、物品、行动进度和知识边界，不能故意
  把基线写弱。

纯提示词基线应使用独立、可复现的 baseline runner；历史实验脚本不属于当前公开运行入口。

### 固定世界

使用一个原创的双地点、双角色实验世界，不依赖任何现成作品或隐含知识。实验描述明确给出：

- 角色甲在北岸祠堂，角色乙在东港公寓，角色丙知道一条局部规则，玩家在北岸祠堂。
- 入睡后才可能交换；占据持续到再次入睡。
- 身体主人不记得被占据期间发生的事。
- 第 7 天黄昏天象事件才到期。
- 初始物品：场景物品、角色随身物品和玩家的一枚硬币。

### 12 步固定输入

| 步 | 时刻 | 玩家输入 / 时间变化 | 预注册检查点 |
|---|---|---|---|
| 1 | 第1天黄昏 | 问角色甲“你在等谁？” | 角色甲必须在场才可回应 |
| 2 | 第2天清晨 | 把伞挪向角色甲，问她冷不冷 | 伞与互动留痕 |
| 3 | 第2天白昼 | 角色甲开始一项需 0.5 天完成的查找行动 | 不能当场完成 |
| 4 | 第2天黄昏 | 玩家离开北岸祠堂去北坡观测台 | 玩家与角色甲分场 |
| 5 | 第3天清晨 | 玩家等待 0.25 天 | 查找行动应已到期；结果必须有因 |
| 6 | 第3天黄昏 | 仅角色丙在北岸祠堂得知“旧铜箱底有刻痕” | 秘密只属于角色丙及现场者 |
| 7 | 第4天清晨 | 玩家继续在北坡观测台等待 | 角色甲不得隔空回应玩家 |
| 8 | 第4天黄昏 | 玩家回北岸祠堂 | 根据真实位置决定看到谁 |
| 9 | 第4天黄昏 | 若角色甲在场，问“我不在时发生了什么？” | 她只能说自己知道的部分 |
| 10 | 第5天清晨 | 角色丙把旧铜箱移入暗格 | 物品位置/持有状态改变 |
| 11 | 第5天黄昏 | 玩家尝试把硬币交给角色甲 | 不在场则必须拒绝，不得隔空交付 |
| 12 | 第5天深夜 | 请求当前快照 | 明天是第6天，不是第7天；天象事件未到期 |

第 3、6、10 步是测试夹具输入，不是要求模型自行编出。两组收到同样事实。

### 机械评分（100 分）

| 指标 | 判定 | 分值 |
|---|---|---:|
| 时间一致性 | 12 个时刻、持续时长、第7天触发均正确 | 20 |
| 位置一致性 | 6 个位置检查点；不存在隔空交互 | 20 |
| 行动完成率 | 开始/进行中/到期/完成顺序正确，且不早不晚 | 20 |
| 信息差 | 对角色丙的秘密做 4 次角色查询，统计 FP/FN | 20 |
| 因果可追溯 | 抽取 10 个状态变化，每个能指出直接前因 | 20 |

单项计算：`得分 = 正确检查点 / 总检查点 × 该项分值`。

额外报告但不混入 100 分：

- 总输入/输出 token、总费用、调用数、重试数；
- 无因新增实体数；
- 人工盲评“像活着的世界”1-5 分；
- 叙述质量1-5分。

人工感受不能覆盖事实错误。先公布机械分，再公布盲评分。

### 最低结论标准

单次 pilot 只说明“有信号/没信号”，不能写“稳定胜过”。正式结论至少运行 3 个
不同随机种子；WorldLedger 五项核心机械指标的均值都更高，且没有一项成本超过
纯提示词 2 倍，才可写“在该实验下稳定胜过纯提示词”。

### 输出文件

```text
worldledger_save/eval/prompt_ab/
  manifest.json          # 模型、温度、脚本哈希、开始时间
  engine_run_N.json
  prompt_run_N.txt
  requests_N.jsonl
  scores.json
  report.md
```

## 方案二：长程检索记忆压力测试（WorldLedger vs RAG 记忆）

### 要回答的问题

当上下文不再无限增长，RAG 能找回相关文字，但没有权威状态和事件校验时，是否仍会
在长程中混淆“曾经提到”“现在成立”“某人知道”和“动作已经完成”？

### 两组定义

**A. WorldLedger**

- 当前引擎与当前事件账本。
- 使用同一模型做提案和动作结局。

**C. RAG 记忆基线**

- 每轮保存模型产生的自由文本事件，不建立位置表、物品表、世界钟、动作状态机或
  引用校验。
- 检索完全确定：最近 8 条 + 与当前输入字符二元组相似度最高的 8 条；去重后最多
  16 条。不得人工挑选记忆。
- 系统提示词、世界描述和输出长度与 A 组相同目标；检索文本作为“相关记忆”。
- RAG 可以记住过去，但不能偷偷增加结构化真值表，否则已经变成另一种状态引擎。

### 固定压力世界

使用两个原创世界，每个运行 80 个心跳；避免模型借用现成作品知识。

**世界甲：潮港**

- 3 场景、4 NPC、5 物品。
- 一封密信最初只有甲知道；第 20 心跳乙亲眼读到；第 40 心跳丙只听到走样版本；
  丁始终不应知道正文。
- 两个 NPC 分别计划在第 12、28 心跳完成跨场景行动，其中一次在到期前移走必需物品，
  应中止并重新判断。

**世界乙：坡道镇**

- 一辆持续移动的车、玩家、两名旁观者、一个路障。
- 车在第 10 心跳启动，第 18 心跳到期；第 16 心跳路障被移走。
- 第 18 心跳同一事实必须同时改变车辆、玩家/路人（若仍在路径上）和场景状态；
  不允许只提交“撞了”却没有实体后果。
- 第 50 心跳把车辆转交给另一人，后续旧持有者不得继续操控。

所有时间点和夹具事件预先写入 `gold.json`，运行期间不得修改。

### 四项主指标

#### 1. 长程一致性 LCS

在心跳 10/20/40/60/80 做快照，共检查：

- 当前时间与时刻；
- NPC 位置与可行动状态；
- 物品位置、持有者和当前状态；
- 未完成动作及其到期时间。

`LCS = 正确字段数 / 总字段数`。

#### 2. 信息边界 KBS

对每个秘密，在 5 个检查点分别询问 4 名 NPC。先在 `gold.json` 写下每人应知道的
命题集合。

```text
FP = 不应知道却使用了秘密
FN = 应知道却完全无法回忆
KBS = 1 - (2*FP + FN) / 总查询数
```

FP 权重更高，因为知识泄漏比遗忘更破坏独立角色。

#### 3. 行动承诺 ACS

每项动作记录 `start / due / prerequisites / actual_result`：

- 准时完成：1 分；
- 前置失效后正确中止并留下原因：1 分；
- 提前、延迟超过一个心跳、永久悬挂或无因完成：0 分。

`ACS = 得分动作数 / 总动作数`。

#### 4. 因果可追溯 CTS

随机种子固定，从每局状态变化中抽取 20 条。每条检查：

- 有直接前因；
- 前因发生在结果之前；
- 引用的实体当时存在；
- 多实体事件没有半提交。

四项全对记 1，否则记 0。`CTS = 合格变化数 / 20`。

### 成本与稳定性

每组每个世界先跑 1 次 pilot；协议无 bug 后各跑 3 个种子，共 6 局/组。

报告：

```text
总 token
每心跳 token
每 10k token 的正确状态字段数
每元成本的合格因果变化数
LCS/KBS/ACS/CTS 的均值、最小值、标准差
```

只有均值高而最小值很差，不能称为稳定。

### 判定规则

预注册主张成立需同时满足：

1. WorldLedger 的 LCS、KBS、ACS、CTS 四项均值都高于 RAG；
2. 每项至少 3/3 种子胜出，不靠一个幸运局拉高均值；
3. WorldLedger 每 10k token 的正确状态字段数不低于 RAG；
4. 不隐瞒拒绝事件、解析失败、重试和空输出；
5. 人工盲评可以输，但必须单独解释为叙述层问题，不能改写机械结果。

### 输出文件

```text
worldledger_save/eval/rag_long/
  manifest.json
  gold.json
  engine_world_seedN.json
  rag_world_seedN.jsonl
  requests_seedN.jsonl
  audit_seedN.json
  scores.json
  report.md
```

## 给执行者的最终要求

先实现并运行方案一 pilot；把原始记录、评分脚本和报告保存后停止，不自动开始正式
三种子实验。待协议与费用确认后，再运行方案一正式实验或方案二。不得在测试过程中
顺手修引擎；发现引擎 bug 就记录为失败，实验结束后另行修复。
